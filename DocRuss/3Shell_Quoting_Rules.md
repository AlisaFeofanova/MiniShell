# 1. Что такое quoting

**Quoting (кавычки)** — это механизм Shell, который определяет, как интерпретировать символы в командной строке.

Кавычки позволяют Shell:

* сохранять пробелы внутри одного аргумента;
* предотвращать интерпретацию специальных символов;
* объединять несколько частей текста в одно слово;
* разрешать или запрещать expansion переменных;
* не воспринимать `|`, `<`, `>` как операторы.

Например:

```bash
echo hello world
```

имеет два аргумента после `echo`:

```text
hello
world
```

А:

```bash
echo "hello world"
```

имеет только один аргумент:

```text
hello world
```

Таким образом:

> Кавычки изменяют смысл символов в командной строке.

---

# 2. Зачем Shell нужны кавычки

В Shell множество символов имеют специальное значение.

Например:

```text
space
|
<
>
$
'
"
\
*
?
```

Без кавычек Shell может интерпретировать их особым образом.

Например:

```bash
echo hello world
```

Пробел разделяет аргументы.

Но:

```bash
echo "hello world"
```

пробел становится частью аргумента.

Другой пример:

```bash
echo |
```

`|` — это pipe.

Но:

```bash
echo "|"
```

`|` — обычный символ внутри аргумента.

Поэтому:

> Кавычки позволяют сказать Shell: «Воспринимай этот текст как данные, а не как Shell-синтаксис».

---

# 3. Три основных режима

Для `minishell` необходимо понимать три основных контекста:

```text
1. NORMAL — обычный текст
2. SINGLE_QUOTE — внутри '
3. DOUBLE_QUOTE — внутри "
```

Также существует:

```text
4. BACKSLASH — обработка \
```

Поведение символов зависит от текущего контекста.

---

# 4. Текст без кавычек

Обычный ввод находится в состоянии:

```text
NORMAL
```

Например:

```bash
echo hello
```

Shell видит:

```text
echo
hello
```

как два слова.

---

## 4.1 Пробелы

В обычном режиме:

```bash
echo hello world
```

становится:

```text
echo
hello
world
```

Пробел разделяет слова.

---

## 4.2 Операторы

В обычном режиме:

```bash
echo hello | grep hello
```

символ `|` является оператором.

Пример токенов:

```text
WORD "echo"
WORD "hello"
PIPE "|"
WORD "grep"
WORD "hello"
```

---

## 4.3 Специальные символы

В зависимости от реализации Shell специальные символы могут иметь особое значение:

```text
|
<
>
$
'
"
\
*
?
```

Для `minishell` особенно важно правильно обрабатывать:

```text
'
"
$
\
|
<
>
```

---

# 5. Одинарные кавычки

Одинарные кавычки:

```bash
'...'
```

означают:

> Всё внутри одинарных кавычек воспринимается буквально.

Например:

```bash
echo '$USER'
```

`$USER` не раскрывается.

Результат:

```text
$USER
```

а не:

```text
Alice
```

---

## 5.1 Простой пример

```bash
echo 'hello'
```

Результат:

```text
hello
```

Сами кавычки не становятся частью итогового аргумента.

---

## 5.2 Пробелы

```bash
echo 'hello world'
```

Результат:

```text
hello world
```

Это **один аргумент**.

Пробел находится внутри одинарных кавычек, поэтому он не разделяет слова.

---

## 5.3 Специальные символы

```bash
echo '$HOME'
```

Результат:

```text
$HOME
```

Также:

```bash
echo '|'
```

даёт:

```text
|
```

`|` здесь не является pipe.

И:

```bash
echo '>'
```

даёт:

```text
>
```

`>` здесь не является redirection.

---

# 6. Двойные кавычки

Двойные кавычки:

```bash
"..."
```

также позволяют объединить текст в один аргумент.

Например:

```bash
echo "hello world"
```

даёт:

```text
hello world
```

один аргумент.

Но двойные кавычки отличаются от одинарных.

---

## 6.1 Expansion внутри двойных кавычек

Например:

```bash
USER=Alice
```

и:

```bash
echo "$USER"
```

Результат:

```text
Alice
```

То есть `$USER` внутри двойных кавычек может быть раскрыт.

---

## 6.2 Пробелы

```bash
echo "hello     world"
```

Все пробелы сохраняются:

```text
hello     world
```

Это один аргумент.

---

## 6.3 Операторы

```bash
echo "|"
```

не создаёт pipe.

`|` является частью аргумента:

```text
|
```

То же самое:

```bash
echo ">"
```

`>` — обычный символ, а не redirection.

---

# 7. Разница между одинарными и двойными кавычками

Это одна из самых важных частей `minishell`.

| Возможность                              | `'...'`                 | `"..."`    |     |
| ---------------------------------------- | ----------------------- | ---------- | --- |
| Сохраняет пробелы                        | Да                      | Да         |     |
| Сохраняет специальный текст              | Да                      | В основном |     |
| `$VARIABLE` expansion                    | Нет                     | Да         |     |
| `                                        | ` становится оператором | Нет        | Нет |
| `<` становится оператором                | Нет                     | Нет        |     |
| `>` становится оператором                | Нет                     | Нет        |     |
| Кавычки удаляются из результата          | Да                      | Да         |     |
| Можно напрямую вставить такую же кавычку | Нет                     | Нет        |     |

Главное:

```bash
'$USER'
```

означает:

```text
$USER
```

А:

```bash
"$USER"
```

означает:

```text
Alice
```

если:

```text
USER=Alice
```

---

# 8. Кавычки и токенизация

Кавычки напрямую влияют на работу Lexer.

Сравним:

```bash
echo hello world
```

Токены:

```text
WORD "echo"
WORD "hello"
WORD "world"
```

Теперь:

```bash
echo "hello world"
```

Токены:

```text
WORD "echo"
WORD "hello world"
```

Почему?

Потому что пробел внутри кавычек не является разделителем слов.

---

# 8.1 Кавычки сами по себе не являются аргументами

Например:

```bash
echo "hello"
```

Не нужно создавать:

```text
WORD "echo"
QUOTE
WORD "hello"
QUOTE
```

В итоге Shell должен получить:

```text
WORD "echo"
WORD "hello"
```

Кавычки являются частью синтаксиса.

---

# 9. Кавычки не обязательно создают отдельный аргумент

Это очень важный момент.

Например:

```bash
echo "hello"
```

создаёт:

```text
hello
```

один аргумент.

Но:

```bash
echo hello"world"
```

тоже создаёт **один аргумент**:

```text
helloworld
```

И:

```bash
echo "hello"'world'
```

даёт:

```text
helloworld
```

Следовательно:

> Кавычки не обязательно разделяют аргументы. Они могут быть частью построения одного слова.

---

# 10. Объединение текста

Shell может объединять несколько частей в одно слово.

Например:

```bash
echo abc"def"ghi
```

Можно представить как:

```text
abc
+
def
+
ghi
```

Результат:

```text
abcdefghi
```

---

## 10.1 Разные типы кавычек

```bash
echo 'hello'"world"
```

Результат:

```text
helloworld
```

---

## 10.2 Несколько секций

```bash
echo a'b'c"d"e
```

Результат:

```text
abcde
```

Всё это один аргумент.

---

# 11. Пустые кавычки

Пустые кавычки создают **пустую строку**.

Например:

```bash
echo ""
```

Shell передаёт:

```text
argv[0] = "echo"
argv[1] = ""
```

То есть второй аргумент существует, но он пустой.

---

## 11.1 Пустые одинарные кавычки

```bash
echo ''
```

тоже создают:

```text
argv[1] = ""
```

---

## 11.2 Почему это важно

Сравним:

```bash
echo
```

и:

```bash
echo ""
```

В первом случае дополнительных аргументов нет.

Во втором есть один дополнительный аргумент:

```text
""
```

Это важно при построении `argv`.

---

# 12. Пробелы внутри кавычек

Без кавычек:

```bash
echo hello world
```

получаем:

```text
hello
world
```

С кавычками:

```bash
echo "hello world"
```

получаем:

```text
hello world
```

один аргумент.

---

## 12.1 Несколько пробелов

```bash
echo "hello     world"
```

результат:

```text
hello     world
```

Все пробелы сохраняются.

---

## 12.2 Пробелы рядом с кавычками

Рассмотрим:

```bash
echo hello" world "
```

Здесь нет пробела между `hello` и открывающей кавычкой.

Поэтому это один аргумент:

```text
hello world
```

Части:

```text
hello
+
 world 
```

объединяются.

---

# 13. Переменные и кавычки

Shell выполняет expansion переменных в зависимости от контекста.

Допустим:

```bash
NAME=Alice
```

Тогда:

```bash
echo $NAME
```

может дать:

```text
Alice
```

Двойные кавычки:

```bash
echo "$NAME"
```

также дают:

```text
Alice
```

Но одинарные:

```bash
echo '$NAME'
```

дают:

```text
$NAME
```

---

# 14. `$` внутри одинарных кавычек

Внутри:

```bash
'$USER'
```

символ `$` является обычным символом.

Shell не должен искать переменную `USER`.

Например:

```bash
echo '$USER'
```

результат:

```text
$USER
```

Правило:

```text
'...' → переменные НЕ раскрываются
```

---

# 15. `$` внутри двойных кавычек

Внутри:

```bash
"$USER"
```

переменная может быть раскрыта.

Например:

```bash
USER=Alice

echo "$USER"
```

результат:

```text
Alice
```

Главное правило:

```text
'$USER'
    ↓
$USER

"$USER"
    ↓
Alice
```

---

# 16. Обратный слеш

Backslash:

```text
\
```

также используется для quoting.

Он позволяет изменить значение следующего символа.

Например:

```bash
echo hello\ world
```

даёт:

```text
hello world
```

один аргумент.

Backslash защищает пробел от обычной функции разделителя.

---

# 17. Backslash вне кавычек

В обычном режиме:

```bash
echo hello\ world
```

без backslash Shell увидел бы:

```text
hello
world
```

Но `\ ` означает, что пробел нужно воспринимать буквально.

Получаем:

```text
hello world
```

один аргумент.

---

## 17.1 Защита специальных символов

Например:

```bash
echo \|
```

даёт:

```text
|
```

а не `PIPE`.

То же самое:

```bash
echo \>
```

даёт:

```text
>
```

а не redirection.

---

# 18. Backslash внутри двойных кавычек

Внутри двойных кавычек поведение `\` более ограниченное.

В Bash backslash имеет специальное значение перед определёнными символами, в частности:

```text
"
\
$
`
newline
```

Например:

```bash
echo "hello \$USER"
```

даёт:

```text
hello $USER
```

Переменная не раскрывается.

Другой пример:

```bash
echo "hello \"world\""
```

даёт:

```text
hello "world"
```

---

# 19. Backslash внутри одинарных кавычек

Внутри одинарных кавычек:

```bash
'...'
```

backslash не выполняет функцию escape.

Например:

```bash
echo '\$USER'
```

даёт:

```text
\$USER
```

И `\`, и `$` являются обычными символами.

Правило:

```text
'...' → backslash обычный символ
```

---

# 20. Кавычки внутри кавычек

Разные типы кавычек могут находиться друг внутри друга.

## Одинарная кавычка внутри двойных

```bash
echo "it's working"
```

Результат:

```text
it's working
```

Апостроф `'` внутри `"..."` является обычным символом.

---

## Двойные кавычки внутри одинарных

```bash
echo 'he said "hello"'
```

Результат:

```text
he said "hello"
```

`"` внутри `'...'` является обычным символом.

---

## Одинаковые кавычки

Вторая такая же кавычка закрывает текущий контекст.

Например:

```bash
echo 'hello'
```

Первая `'`:

```text
NORMAL → SINGLE_QUOTE
```

Вторая `'`:

```text
SINGLE_QUOTE → NORMAL
```

То же самое с:

```text
"
```

---

# 21. Незакрытые кавычки

Если кавычка открылась, она должна быть закрыта.

Например:

```bash
echo "hello
```

имеет:

```text
"
```

без закрывающей кавычки.

Также:

```bash
echo 'hello
```

имеет незакрытую `'`.

Lexer должен уметь обнаруживать такую ситуацию.

---

# 21.1 Состояния Lexer

Удобно представить Lexer как state machine:

```text
NORMAL
SINGLE_QUOTE
DOUBLE_QUOTE
```

Например:

```bash
echo "hello world"
```

проходит:

```text
NORMAL
   |
   | "
   v
DOUBLE_QUOTE
   |
   | "
   v
NORMAL
```

---

# 22. Удаление кавычек

Кавычки обычно не являются частью итогового аргумента.

Например:

```bash
echo "hello"
```

Shell передаёт:

```text
hello
```

а не:

```text
"hello"
```

То же самое:

```bash
echo 'hello'
```

даёт:

```text
hello
```

---

## 22.1 Почему нельзя удалять кавычки слишком рано

Рассмотрим:

```bash
'$USER'
```

и:

```bash
"$USER"
```

Они выглядят похоже, но имеют совершенно разное поведение.

Если удалить кавычки до того, как будет выполнен expansion, Shell потеряет информацию:

```text
'$USER'
```

должно остаться:

```text
$USER
```

а:

```text
"$USER"
```

должно стать значением переменной.

Поэтому:

> Информация о quote context должна сохраняться достаточно долго, чтобы последующие стадии могли правильно обработать текст.

---

# 23. Кавычки и операторы

Кавычки могут полностью изменить значение символа.

Без кавычек:

```bash
echo |
```

`|` — оператор:

```text
PIPE
```

С кавычками:

```bash
echo "|"
```

`|` — обычный текст:

```text
WORD "|"
```

То же самое:

```bash
echo >
```

→

```text
REDIR_OUT
```

Но:

```bash
echo ">"
```

→

```text
WORD ">"
```

---

# 24. Кавычки и редиректы

Рассмотрим:

```bash
cat < input.txt
```

Здесь:

```text
<
```

является оператором:

```text
REDIR_IN
```

Но:

```bash
echo "< input.txt"
```

создаёт один аргумент:

```text
< input.txt
```

Никакого redirection нет.

---

## 24.1 Кавычки для имени файла

Очень распространённый случай:

```bash
cat < "my file.txt"
```

Здесь:

```text
<
```

остаётся redirection.

А:

```text
"my file.txt"
```

является именем файла с пробелом.

Концептуально:

```text
REDIR_IN
WORD "my file.txt"
```

---

# 25. Кавычки и Pipe

Без кавычек:

```bash
echo hello | grep hello
```

получаем:

```text
echo
hello
PIPE
grep
hello
```

Но:

```bash
echo "hello | world"
```

получаем:

```text
echo
hello | world
```

`|` является частью аргумента.

# 26. Кавычки и Expansion

Рассмотрим:

```bash
NAME=Alice
```

### Без кавычек

```bash

```

Результат:

```text

```

### Двойные кавычки

```bash

```

Результат:

```text
Alice
```

### Одинарные кавычки

```bash

```

Результат:

```text
$NAME
```

Главное правило:

```text
'...'  → expansion не выполняется
"..."  → expansion выполняется
```

# 28. Что должен делать Lexer

Lexer должен понимать quote context.

Его основные задачи:

```text
✓ Распознавать '
✓ Распознавать "
✓ Отслеживать quote state
✓ Не разделять пробелами текст внутри кавычек
✓ Не превращать quoted operators в операторы
✓ Объединять quoted и unquoted текст в один WORD
✓ Обнаруживать незакрытые кавычки
✓ Сохранять информацию, необходимую для expansion
```

Например:

```bash
echo hello"world"
```

должно быть распознано как **одно слово**.

---

# 28.1 Пример работы Lexer

Ввод:

```bash
echo "hello | world"
```

Lexer идёт примерно так:

```text
e c h o
    ↓
NORMAL

"
↓
DOUBLE_QUOTE

hello | world
     ↓
всё считается частью WORD

"
↓
NORMAL
```

Поэтому `|` не становится `PIPE`.

---

# 29. Что должен делать Expansion

Expansion отвечает за раскрытие переменных.

Например:

```text
$USER
$HOME
$?
```

Но expansion должен учитывать quote context.

Например:

```bash
echo '$USER'
```

нельзя преобразовать в:

```text
Alice
```

А:

```bash
echo "$USER"
```

можно преобразовать в:

```text
Alice
```

Поэтому Lexer/parser должны передать expansion достаточно информации о том, где находится текст.

# 30. Типичные ошибки

## Ошибка 1 — использовать простой `split(" ")`

Например:

```bash
echo "hello world"
```

Такой подход даст:

```text
"hello
world"
```

что неправильно.

Правильно:

```text
hello world
```

один аргумент.

---

## Ошибка 2 — считать кавычки отдельными аргументами

Неправильно:

```text
WORD "hello"
WORD "world"
```

для:

```bash
echo "hello world"
```

Правильно:

```text
WORD "hello world"
```

---

## Ошибка 3 — оставлять кавычки в `argv`

Неправильно:

```text
"hello"
```

Правильно:

```text
hello
```

---

## Ошибка 4 — раскрывать переменные внутри `'...'`

Неправильно:

```bash
echo '$USER'
```

→

```text
Alice
```

Правильно:

```text
$USER
```

---

## Ошибка 5 — воспринимать quoted operator как оператор

Неправильно:

```bash
echo "|"
```

→

```text
PIPE
```

Правильно:

```text
WORD "|"
```

---

## Ошибка 6 — разделять concatenated text

Неправильно:

```bash
echo hello"world"
```

→

```text
hello
world
```

Правильно:

```text
helloworld
```

---

## Ошибка 7 — игнорировать пустые аргументы

Неправильно считать:

```bash
echo ""
```

эквивалентом:

```bash
echo
```

У первого есть пустой аргумент.

---

## Ошибка 8 — не хранить quote state

Если Lexer не знает, что он находится внутри:

```text
DOUBLE_QUOTE
```

он может неправильно распознать:

```bash
echo "hello | world"
```

как pipe.

---

## Ошибка 9 — удалять кавычки слишком рано

Нельзя сразу превращать:

```bash
'$USER'
```

в:

```text
$USER
```

и забывать, что этот текст был внутри single quotes.

Иначе expansion может ошибочно раскрыть переменную.

```text
                     v

              |    LEXER    |

                     |

          |          |          |

                EXPANSION
                     |
                     v

                     |
                     v
               FINAL ARGV
                     |

                 EXECUTION
```

```bash
'$USER'
```

→ `$USER`

Expansion не происходит.

### Rule 3 — двойные кавычки

```bash

```

→ значение `$USER`.

### Rule 4 — concatenation

```bash

```

→

```text

```

---

### Rule 5 — разные quote sections

```bash

```

→

```text

```

### Rule 6 — quoted operators

```bash
"|"
```

→ обычный текст.

Не pipe.


```text
               +-- " --> NORMAL
```

# Итог для Minishell

Quoting нельзя рассматривать как просто «удаление кавычек».

Правильная обработка выглядит примерно так:

```text
1. Получить raw input
        ↓
2. Lexer анализирует quote context
        ↓
3. Определить границы WORD
        ↓
4. Не воспринимать quoted operators как операторы
        ↓
5. Сохранить информацию о quote context
        ↓
6. Parser строит структуру команды
        ↓
7. Expansion обрабатывает $VARIABLE
        ↓
8. Single quotes предотвращают expansion
        ↓
9. Double quotes позволяют expansion
        ↓
10. Выполнить quote removal
        ↓
11. Получить правильный argv
        ↓
12. Execute
```

Если вы понимаете:

```text
✓ SINGLE QUOTES
✓ DOUBLE QUOTES
✓ BACKSLASH
✓ QUOTE STATE
✓ TOKENIZATION
✓ CONCATENATION
✓ EMPTY ARGUMENTS
✓ VARIABLE EXPANSION
✓ QUOTED OPERATORS
✓ QUOTE REMOVAL
✓ UNCLOSED QUOTES
```

то вы понимаете основную часть **Shell Quoting**, необходимую для реализации `minishell`.
